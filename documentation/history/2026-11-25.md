# 2026-11-25

## Edit notes in the side panel

- New ✎ Edit / 👁 Preview toggle in the side panel action row. Edit mode mounts Obsidian's markdown embed via `app.embedRegistry.getEmbedCreator(file)` with `editable = true`, then `loadFile()` + `showEditor()` — the same path Canvas file cards and footnote popovers use (checked against Obsidian 1.13 app bundle).
- `src/app/utils/markdown-embed.ts`: typed wrapper + runtime guards (`getMarkdownEmbedCreator`, `isMarkdownEmbed`, `createMarkdownEmbed`, `flushMarkdownEmbed`). Spec covers guard and flush logic.
- Decision: flush pending edits explicitly before unloading — the embed's `requestSave` is a 2 s debounce and nothing flushes it on unload.
- Decision: focus in the editor sets `workspace.activeEditor` so formatting hotkeys and editor commands target it (Canvas does the same).
- `renderToken` guards async renders so fast node switching cannot mount a stale editor.
- View `handleKeyDown` now ignores events from inside `.ge-side-panel`; before, Tab/Enter/arrows/Escape were swallowed by graph navigation.

## Edit mode by default

- Side panel now opens in edit mode (`mode` default `'edit'`); Preview toggle still available. Falls back to preview when the embed API is missing.

## Properties collapsed in the panel editor

- Symptom: edit mode showed only the "Properties" header. Cause: Obsidian's markdown embed class keeps a static `collapseProperties = true` shared by all embeds unless `useLocalPropertiesFoldState` is set.
- Fix: `createMarkdownEmbed` sets `useLocalPropertiesFoldState = true` before `loadFile()`, so the collapse state comes from the note's fold info (from = 0 fold), same as a tab.

## Reveal the selected note's out-of-base neighbors

- New view toggle `revealSelectedNeighbors` (default on). View tracks `selectedNodeId`; `selectNode()` rebuilds the graph when the selection changes. `rebuildGraph` passes the result through `revealNeighborhood` (`src/app/services/graph-neighborhood.ts`).
- Incoming links: candidates from `metadataCache.resolvedLinks`, re-checked with `getLinkTargets` for `frontmatter`/`body` edge sources. `getLinkTargets` now takes metadata instead of a Base entry and is exported.
- Revealed nodes read metadata via `metadataCache.getCache(path)` (not Base entries), so `status` coloring works for notes the Base filters out. The existing `showExternal` path still builds outside-entry externals with empty frontmatter — not changed.
- `carryOverPositions` (`src/app/utils/layout-carry-over.ts`) in `GraphCanvas.setData`: keeps positions across rebuilds and seeds new nodes next to a neighbor, so a selection does not re-layout the graph.
- Decision: one hop only. Walking further = click a revealed node.

## Fix: saved camera not applied on reopen

- Symptom: `camera` was saved in the Base config but reopening still zoomed to fit.
- Cause: state was read in `onload` → `buildUI`, before Bases hands the view its config/data, so reads were empty. (Node spacing worked because `syncConfigToCanvas` re-reads on every `onDataUpdated`.)
- Fix: `restoreViewState()` runs once at the start of the first `rebuildGraph` that has data (camera, selected note, left panel); selection is re-applied after that render (`pendingSelectionRestore`). Flags reset in `onunload`.

## Double-click reliability

- Ray: card expands, but double-click often needs several tries (tested on Mac; plugin folder syncs, a debug log in the plugin folder did not, so a temporary log note in the vault was used and then removed).
- Log showed click gaps of 0.7–1.6 s between clicks Ray meant as double-clicks: the first click's select + reveal + rebuild keeps the main thread busy, and force-graph reports clicks on the next animation frame, so the `Date.now()` 400 ms window missed them.
- Fix: native `dblclick` listener on the canvas container; node = last clicked node (≤1 s) or hovered node. Second click within 500 ms is ignored for node click and background click.

## Click no longer opens the side panel

- Ray: does not want the side panel to pop up on the first click (cards are now the main way to read/edit).
- Click selects only; panel follows clicks while open. New context menu entry "Open in side panel". `sidePanelOpen` view config key; restoreSelection reopens the panel only when it was open.
- Follow-up: clicking the already selected node again opens the panel (500 ms delay, cancelled by dblclick).
